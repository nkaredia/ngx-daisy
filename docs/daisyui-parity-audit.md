# daisyUI parity audit

Reference: installed daisyUI **5.7.50**, also reported by the [current official catalog](https://daisyui.com/components/) on October 24, 2026. Reviewed all **68 catalog families**, their public input/class mappings, templates and local SCSS against the installed component CSS. Extra Icon and Form Field helpers are outside the native catalog.

This is a source/API audit, with targeted browser checks, **not** a certification that every variant is visually identical. A family existing, a native class string being present, or a passing behavior test is insufficient to establish visual parity. “Mapped” below only means that the native class/part surface was found and this pass found no specific omission. Light/dark, size, responsive, RTL, state, reduced-motion and nested-theme comparisons remain necessary.

## Confirmed and corrected in this pass

- **Tabs:** `[dsyTabPanel]="index"` is an Angular input binding, not a guaranteed DOM attribute. Layout/hidden selectors depended on that attribute. Added the stable `.dsy-tab-panel` host class, switched structural selectors to it, changed regression fixtures to bound inputs and removed the showcase-only visibility workaround.
- **Menu:** class-controlled dropdowns lacked the `menu-dropdown-show` mapping. Added `opened` to both dropdown and toggle directives, mapped prefixed open classes, exposed aria-expanded and made closed contents inert. The application owns the click handler and ID/aria-controls connection.
- **Badge, Chat Bubble, Status:** the components forced `neutral` when color was omitted. Native base classes have different background/foreground defaults. Color is now optional; existing explicit neutral usage is unchanged. **Migration:** set `color="neutral"` where the previous forced neutral appearance was desired.

## Follow-up implementation — October 25, 2026

The concrete differences identified in this audit have now been addressed: native loader masks and sizes, provider-style Angular calendar markup, image hover zones, native Hover3d variables/easing, intrinsic carousel layouts, the in-stage Diff handle, grid disclosure motion, lifted/bottom tab bridges, megamenu trigger/highlight styling, native input/select wrappers, Fieldset Label and Table Row helpers. Native defaults were restored for Rating, Tabs, Timeline, Collapse and Swap. Modal motion and dropdown metrics were aligned. Tooltip arrows now retain the native mask and follow the actual CDK fallback side.

Angular/CDK ownership is intentionally retained for forms, date arithmetic, portals, focus, inertness and accessible controls. Page/determinate loaders and optional numbered gallery controls remain explicit extensions. This implements the known findings; it is not a pixel-perfect certification of every possible daisyUI variation.

### Migration notes

- Carousel: use `slideSize="full"` to retain full-viewport slides; use `viewportClass` for gaps or vertical height.
- Hover Gallery: use `[controls]="true"` to keep numbered buttons. The default is image-hover/keyboard navigation, with at most ten images.
- Loading: include daisyUI `loading`; normal-speed auto animation uses native masks. Custom speed/motion, determinate ring/bar and reduced-motion fallback remain library visuals.
- Calendar: include daisyUI `calendar`. No React/DayPicker runtime is required.
- Defaults: use `color="warning"` on Rating, `variant="border"` on Tabs, `orientation="vertical"` on Timeline, `indicator="arrow"` on Collapse, and `variant="ghost"` on Swap to retain the earlier library appearance.

## Verification and completion criteria

The existing Angular tests cover interaction/forms and the CSS configuration matrix covers themes, include/exclude and prefixes; neither substitutes for visual reference comparisons. Regression checks were extended for bound tab inputs, submenu open state and native default colors. Browser smoke checks loaded all 70 showcase routes at the desktop viewport, confirmed their page headings and found no document-level horizontal overflow. These checks do not cover all interactive states or responsive widths.

Before claiming 100% fidelity, create a native daisyUI and ngx-daisy fixture for **each documented variation**, using identical markup content, theme and viewport. Compare geometry, computed colors/type/spacing, borders/shadows, motion and pointer/keyboard states. Include custom/nested themes, RTL and both prefix modes. Document intentional Angular extensions separately from base daisyUI visuals.

Important references: [Tabs](https://daisyui.com/components/tab/), [Menu](https://daisyui.com/components/menu/), [Input](https://daisyui.com/components/input/), [Calendar](https://daisyui.com/components/calendar/), [Loading](https://daisyui.com/components/loading/), [Hover Gallery](https://daisyui.com/components/hover-gallery/). Exact CSS evidence is in `node_modules/daisyui/components/` for the installed version; it was used to avoid confusing responsive selectors, legacy aliases, utility classes and provider-owned calendar states with missing Angular APIs.

Validation for the original audit: production library/showcase build passed; 109 library tests, 22 showcase tests, 3 builder tests and all 14 CSS configurations passed. The existing initial-bundle warning remains (793 kB versus the 600 kB warning budget; the build succeeds). All 70 desktop routes loaded without document horizontal overflow. Bound tab panels were checked in-browser: the active panel displays as block and inactive panels display none even without a dsyTabPanel DOM attribute.

Follow-up validation (25 October): production library/showcase builds passed; 114 library tests, 22 showcase tests, 3 builder tests and all 14 CSS configurations passed. The initial bundle is approximately 826 kB, with the existing 600 kB warning budget. These changes resolve the concrete source-audit findings; full visual certification across every theme, viewport and state remains a separate verification task.

Follow-up browser checks loaded all 70 desktop routes without document-level horizontal overflow. Targeted checks confirmed native loader masks, 38.4px Diff handles and keyboard position updates, lifted top/bottom panel borders, gallery keyboard selection, clickable Hover3d content, intrinsic/full carousel widths, megamenu highlight geometry and tooltip arrow masks. At 320px, calendars retain native day-cell sizing and scroll within their own host without widening the page.
