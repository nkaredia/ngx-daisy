Angular

Import once. Use a native button.

Import DsyButton from @ngx-daisy/cdk/button in your standalone component, then add dsyButton to a <button> or <a>. Your app must already compile Tailwind and daisyUI and scan the library for its styles.

Bind inputs to signals or ordinary component properties. Handle actions with Angular’s native (click) binding. The component does not make requests or own your loading state.

Loading also prevents activation.

The spinner is decorative. Keep the action’s text visible, and announce completion or errors with a separate status message.

Navigation and router links

Use a button for an action and an anchor for a destination. RouterLink, href, target, and rel remain native Angular or HTML concerns. Import RouterLink alongside DsyButton when using the Angular router.

Forms and submit actions

The default button type is button, so it does not submit a surrounding form. Set type="submit" deliberately and keep validation and submission in your form. Use (ngSubmit) with Angular forms; avoid submitting the same request from both (click) and (ngSubmit).

Buttons are actions, so they do not take formControl, formControlName, or a Signal Forms field binding. Bind disabled and loading from your form and request state. This works with Reactive Forms, template-driven forms, and Signal Forms.

Appearance

Theme, size, and composition

Colors come from the active daisyUI theme. Use semantic choices such as primary for a main action, error for a destructive action, and ghost or outline treatments for lower emphasis. Color should support the label, rather than carry the meaning alone.

Visual hierarchy

Use one prominent action per group. Pair a solid primary action with a quieter secondary action.

Layout and shape

Use block for full-width actions and square or circle for icon-only buttons. Keep related actions consistent in size.

Projected content

Put text or your icon component inside the button. DsyIcon can wrap your chosen provider. Avoid nesting links, inputs, or other buttons.

Application classes are merged with the generated daisyUI classes. Use Tailwind utilities for spacing and layout, and theme tokens for a consistent surface. When configuring daisyUI or Tailwind prefixes, configure the library’s matching prefix provider too. Theme Builder previews how these tokens affect every component.

Events and state

Use native (click), (focus), and (blur) events. There are no custom outputs or two-way models. The read-only isDisabled() computed state is true when either disabled or loading is true. Boolean inputs accept bare attributes, such as <button dsyButton disabled>, and property bindings.

Accessibility

Keep native interaction clear

  • Give every action a name. Visible text supplies it by default. Set aria-label on icon-only buttons and keep their icons decorative. Tooltips provide supporting context.
  • Preserve native keyboard behavior. Buttons activate with Enter or Space; links activate with Enter. Keep focus styles visible and prefer the natural tab order.
  • Expose toggle state explicitly. For an on/off action, bind aria-pressed along with the visual active input. A button’s active appearance alone does not announce selection.
  • Explain unavailable actions. Disabled buttons cannot receive focus. Put useful explanations in nearby text instead of relying on hover.
  • Check the chosen theme. Verify text contrast, recognizable focus, and touch target size, especially with custom colors and compact sizes.
