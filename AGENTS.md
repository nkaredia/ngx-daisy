# Project conventions

Read docs/requirements.md for the recovered product requirements and outstanding scope.

Use Yarn 4 with the node-modules linker. Keep yarn.lock committed; do not generate an npm lockfile.

Run Prettier on changed code and configuration files after every code change, before completing the task.

Use SCSS for stylesheets and inline component styles. Keep Angular CLI generation defaults set to SCSS.

Preserve daisyUI customization support. Read docs/daisyui-customization.md when adding or changing component styling. Generate native daisyUI class lists through injectDaisyUIClasses from @ngx-daisy/cdk/config (it includes compatibility aliases for daisyUI's conditional selectors with a Tailwind prefix), retain complete unprefixed class literals for source detection, inherit theme tokens and keep visual defaults overridable by app utilities. Expose styling access to internal visual slots where projection is not enough. Keep disabled/hidden/inert and reduced-motion safeguards. Extend scripts/check-daisyui-config.mjs when new native class families or customization dependencies are introduced; yarn test includes this CSS matrix.

Use Angular CLI generators where possible. Components must be standalone, OnPush and ViewEncapsulation.None, with modern signal APIs and no Zone.js. Use dsy selectors and Dsy class names. Use Angular CDK for interaction foundations and daisyUI/Tailwind for appearance.

Each component family belongs in a secondary entry point with its own ng-package.json and public-api.ts. Keep the root entry point free of component exports. The npm package name is provisional and private.

Run yarn build before yarn test when validating changes: the showcase imports the built library. Use yarn start for the showcase and yarn watch:lib in another terminal for library development.

Give every component family a dedicated lazy-loaded showcase demo route and a descriptive page title. Add new pages to the shared component catalog that drives both routing and navigation; keep the app shell focused on shared responsive navigation and theme state. Preserve theme selection across routes. The showcase catalog lists all current component routes; the root and unknown paths redirect to /buttons. Reuse the drawer family for shell navigation: side mode from 1024px, closed over mode below it. Close mobile navigation after a route change without restoring the opener's focus, then focus the new page content.

Keep DsyIcon a content projection wrapper. Apps own icon packages, imports, registrations and tree shaking; ngx-daisy supplies size, semantic daisyUI color and accessibility. Do not add a default provider, icon registry, provider adapters, discovery generator or icon installation schematic. Use individual @lucide/angular icon imports as the default in the showcase. Scope icon styling to dsy-icon and document provider markup, Shadow DOM and inline styling limits.

The six daisyUI Actions families are implemented; see docs/actions.md. Keep shared modal lifecycle in @ngx-daisy/cdk/overlay so drawers and dialogs share focus, inertness and scroll locking. Portalled dropdowns copy inherited theme variables to an external scope; panelClass remains utility-overridable. Preserve daisyUI’s native theme-controller exception: daisyUI prefix only, never the Tailwind namespace.

All 15 daisyUI Data Input families and the form-field support entry point are implemented; see docs/data-inputs.md. New composed form controls use Angular 22 FormValueControl/FormCheckboxControl contracts with signal models and touch outputs; do not add parallel CVAs unless required by a distinct compatibility need. Native styling directives preserve Angular's native bindings/accessors. Keep Angular validation as the source of truth, with reactive error presentation, labels/descriptions and CDK interaction foundations. Signal Forms constraints belong in schemas. Each Data Input family has its own route listed in the showcase catalog.

All 19 daisyUI Data Display families are implemented; see docs/data-display.md. Keep CDK accordion coordination, CDK table data source compatibility, native keyboard controls and semantic projected markup. Do not add autoplay or timer ownership to display-only components. Carousel inactive slides are inert. Diff layers are noninteractive, with a native range control for position. Motion effects respect reduced motion. Each family owns a dedicated lazy route in the shared catalog.

All 68 daisyUI 5.7.50 families are now represented; docs/catalog.md maps them to entry points and the 70 showcase routes. See docs/remaining-components.md for navigation, feedback, layout and mockups. Keep site navigation as native links/lists; use Dropdown for ARIA action menus. Tabs use CDK focus management and hidden/inert inactive panels. Megamenu and Tooltip use CDK overlays with inherited theme scopes; Tooltip uses CDK AriaDescriber and tooltipDisabled must stay independent of native disabled. Toast messages persist by default; optional timers pause for hover/focus and clean up on destruction. Mockups preserve projected semantics. Existing reported issues are reserved for a later pass.

Showcase navigation uses daisyUI category order from showcase-pages.ts. Keep category metadata with each route, group Icons under Data Display and Form Field under Data Input, and preserve one link per route. Sidebar branding reads the library version from its package.json. Only the category list scrolls; branding and the footer theme control stay visible.

Mobile showcase titlebar contains the icon-only navigation opener and brand/version; omit duplicate branding inside the mobile drawer. Desktop has no titlebar and keeps sidebar branding. Preserve accessible button labels and expanded/controls relationships.

The showcase build and serve targets use tools/showcase-builder and Angular's exported experimental build APIs. The playground esbuild loader intercepts playground.ts imports, resolves components[].class and injects generated props only into in-memory module text. Never write generated props to authored playground files. Keep plain configuration modules separate from Angular-decorated classes. Invalidate extraction for rebuilds and track source/type dependencies. Angular type checking sees authored source, not the runtime augmentation; the extractor uses its own non-emitting TypeScript program. Preserve Angular option forwarding, streaming results and context teardown. Root postinstall synchronizes installed Angular option schemas into ignored local files.

Playground contracts live in projects/showcase/src/app/playground/playground.types.ts. Authored playgrounds use the Playground type with optional generated props. Every extracted property has a discriminated action: select for finite literals, toggle for booleans, text for strings, number for numbers, and unsupported for complex/mixed broad types. Classify resolved read types, not transform accepted types, and keep nullable/optional flags separate. Keep generated metadata type-checked against this contract and never persist it to authored source.

The internal showcase Playground component lives in playground/playground.component.ts (reserve the exact filename playground.ts for loader configurations). Register configs once on the showcase page with providePlayground(...configs). Pass only one preview class through the component input to each renderer instance, and create separate instances for config.previews. Resolve metadata internally by class identity; each instance has independent state and renders exactly one preview. Each preview receives that instance’s values array in library-component order; compound examples can still use multiple input groups. Do not map preview indices to component indices or require handwritten preview templates. Keep values grouped by config.components order and keyed by source member name, preserving public aliases for labels. The propsPosition model supports side/bottom with a responsive stacked fallback; position changes preserve state. Keep action components in the exhaustive registry, preserve typed literal values, and expose reset/unset/null behavior without executing default expressions. Examples remain ordinary Angular components under each demo's example folder.

Playground configs optionally list inlinePreviews descriptors with title and component for compact examples. Render each with InlinePreviewShell, which owns the card, heading and accessible section and hosts the render-only InlinePreview. Keep all showcase shell markup/styles outside example components; do not create a full playground, resolve input-property metadata or inject values into these examples. Keep defaults and local example state self-contained. Full interactive previews remain under previews, each with an independent Playground instance. Example source stays in the demo’s example folder.

Keep inline preview example components in a single .ts file, using inline templates and inline SCSS only when needed. Full interactive preview examples retain their separate HTML/SCSS files. Keep showcase shells outside both kinds of example.

Extract example source in memory from preview class declarations and their literal Angular template/style resources. Preserve authored contents exactly and watch external resource changes. Keep exampleSources optional in the typed config; never persist generated sources. Shared ExampleCode renders textContent (never innerHTML) with accessible file tabs, collapse and copy feedback. Both Playground and InlinePreviewShell obtain source metadata from the page-scoped configuration; inline rendering itself stays independent of registration.

Inline preview shells always show template-only source by default. Extract literal inline templates as virtual HTML entries in builder memory, removing embedding indentation only; keep full TS snapshots intact. Use static markup for button inline variations. Include supporting TS only through the optional showTypescript descriptor/input. Full playground source remains collapsible with complete files.

The October 25 parity alignment uses native loading masks by default, DayPicker calendar CSS hooks without a third-party runtime, intrinsic carousel slides (slideSize=full is opt-in), image hover zones with optional gallery controls, stage-overlay Diff input, native Hover3d variables, grid disclosure motion, lifted-tab bridges and a megamenu active surface. Keep the calendar's provider rdp-* names free of daisyUI's prefix while applying Tailwind's namespace/conditional aliases. Keep native input/select wrapper appearance on the wrapper; nested controls retain Forms/ARIA/error state without a duplicate surface. Default swaps/tabs are plain, timelines horizontal and ratings base-content. See docs/daisyui-parity-audit.md for migrations and verification boundaries.

Every catalog route now registers a full playground configuration and example under its own demo/example folder, retaining curated demos. Keep every supported scalar control bound to the corresponding preview; use explicit realistic fixtures for complex inputs. Full playground examples should read as relatable product scenarios rather than isolated controls: give content clear hierarchy, center compact compositions, use theme tokens, and verify narrow-screen containment. Native select action options must bind selected state so non-first literal defaults display correctly. Preserve local state on unrelated property edits using primitive computed intermediaries before linkedSignal/effects. Playground Reset intentionally recreates only its preview to restore local form/model state. Keep page/floating overlays contained where possible and retain explicit dismissal for modal samples.
